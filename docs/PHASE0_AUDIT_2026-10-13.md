## ۱. جمع‌بندی اجرایی

پروژهٔ واقعی یک برنامهٔ مشترک React/Vite است که در Windows با Electron و در Android با یک Activity جاوا و WebView امن‌شده اجرا می‌شود. این معماری در وضعیت فعلی حفظ می‌شود؛ جایگزینی آن با پروژهٔ Compose پیوست‌شده یک بازنویسی Android-only، ناسازگار با نسخهٔ Windows و خلاف قاعدهٔ حفظ پروژهٔ موجود است.

نسخهٔ اعلام‌شده در سورس و هر دو تنظیم بسته‌بندی `2.5.0` است. نصب‌کنندهٔ موجود در `Downloads/Programs` نسخهٔ `2.1.0` دارد. فایل یا نصب نسخهٔ `2.4.0` در مسیرهای بررسی‌شده پیدا نشد؛ بنابراین سازگاری باینری، package id، دیتابیس یا امضای ۲.۴.۰ هنوز **قابل تأیید نیست**.

## ۵. ممیزی Android

- application id: `org.jamealtafasir.mobile`
- minSdk: 24؛ targetSdk/compileSdk پیکربندی‌شده: 37
- permission: هیچ `uses-permission` در manifest پایه وجود ندارد.
- `usesCleartextTraffic=false` ثبت شده است.
- Activity اصلی صریحاً `exported=true` است و component دیگری وجود ندارد.
- JavaScript برای React فعال است، اما file/content access خاموش، mixed content ممنوع، cookie خاموش و host داخلی محدود شده است.
- هیچ `addJavascriptInterface` وجود ندارد.
- Release بدون چهار متغیر محیطی امضا عمداً fail می‌شود؛ keystore در مخزن نیست.
- `REQUEST_INSTALL_PACKAGES` در هیچ flavor وجود ندارد.

مانع بیلد محلی: JDK/`JAVA_HOME` روی این دستگاه در دسترس نیست. خطای واقعی Gradle ثبت شد و APK ساخته‌شده‌ای ادعا نمی‌شود.

## ۶. ممیزی Windows/Electron

- `contextIsolation=true`، `nodeIntegration=false`، `sandbox=true` و `webSecurity=true` است.
- ناوبری خارجی و webview مسدود و تنها پیوندهای منبع allowlist شده‌اند.
- CSP، `nosniff` و پروتکل محلی محدود به GET فعال‌اند.
- Binary خود Electron در `node_modules/electron/dist` موجود نیست؛ بنابراین setup جدید در این فاز ساخته نشده است.
- گواهی امضای کد Windows فراهم نیست؛ حذف هشدار SmartScreen/اعتبار ناشر قابل تضمین نیست.

## ۷. بستهٔ کمکی `mansour-source-safety-patch.zip`

- SHA-256: `1E6A30B46FB4DF13E5EC76ECDCBFDCAF4AE9920638E0C2A11FCA6D0DF2DF1884`
- ۵۱ فایل و ۳۶۶٬۶۳۷ بایت محتوای بازشده؛ مسیرهای archive فاقد traversal بودند.
- بسته یک پروژهٔ مستقل Compose با namespace نمونه است، نه patch مستقیم پروژهٔ فعلی.
- فقط ۵۷ سازندهٔ آیهٔ واقعی دارد و برای سوره‌های دیگر متن placeholder تولید می‌کند؛ این داده وارد برنامه نشد.
- Firebase AI/AppCheck، Gemini key flow، URL صوتی سخت‌کدشده، package id متفاوت و release signing ناقص دارد؛ این قسمت‌ها وارد نشدند.
- Gradle wrapper executable/JAR کامل ندارد و به‌تنهایی خروجی قابل اتکا نیست.

بخش‌های استفاده‌شده:

1. رویکرد fail-closed ممیزی منبع به `scripts/audit_source.py` منتقل و برای معماری واقعی بازنویسی شد.
2. سناریوهای امنیتی ارائه‌شده در `tests/security` ثبت و به تست قابل اجرا/قابل BLOCK تبدیل شدند.
3. منطق نرمال‌سازی آن با پیاده‌سازی موجود مقایسه شد؛ نسخهٔ موجود پوشش و تست بیشتری داشت و جایگزین نشد.
4. پالت سبز/طلایی و RTL از قبل در پروژهٔ اصلی وجود داشت؛ کد Compose کپی نشد.

## ۹. مشکلات اولویت‌دار

### P0 — مانع انتشار

1. نبود JDK و APK تست‌شده.
2. نبود کلید امضای نسخهٔ قبلی و نبود امکان مقایسه با امضای ۲.۴.۰.
3. نبود ۲۵ بستهٔ تفسیر معتبر و آیه‌نگاشت‌شده.
4. نبود نسخهٔ ۲.۴.۰ برای آزمون upgrade/migration.
5. نبود فایل‌های فونت رابط که CSS ادعای بارگذاری آن‌ها را دارد.

### P1 — پایداری و مقیاس

1. `App.jsx` تک‌فایل و بزرگ است و باید بدون بازنویسی کامل به ماژول‌های کوچک‌تر تقسیم شود.
2. `content.json` کامل در RAM بارگذاری می‌شود؛ این روش برای ده‌ها تفسیر مناسب نیست.
3. localStorage ظرفیت و تراکنش کافی برای پژوهش‌های بزرگ ندارد.
4. SQLite/FTS5، migration و جداسازی واقعی دیتای کاربر از بسته‌های محتوا هنوز ساخته نشده است.
5. download manager امن، checksum، نصب اتمیک، Zip Slip/Zip Bomb guard و rollback وجود ندارد.

### P2 — امکانات تکمیلی

تم سپیا، کاتالوگ آنلاین، صوت، واژه‌نامه، حدیث، خروجی Word/PDF/Markdown، RAG و ابزار پژوهش چندپنله.

1. معماری مشترک فعلی حفظ شود؛ مهاجرت کامل به Flutter/Compose فعلاً توصیه نمی‌شود.

5. یک بستهٔ آزمایشی کوچک و مجاز وارد، جست‌وجوی FTS5 و نمایش بازهٔ آیات تست شود.
